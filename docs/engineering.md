# Engineering decisions and operations

## Boundaries and identity
NestJS composes domain/application services and infrastructure; Prisma rows stay in infrastructure (and direct test fixtures). No Redis or generic queue framework. Existing secure-access decisions are in s01-engineering.md. HTTP errors expose stable codes and correlated request IDs, never raw database/network exceptions. All mutations require the authenticated session, exact configured origin and session-bound CSRF. Every resource query includes ownership; foreign/nonexistent IDs return 404. IDs/URLs in query strings are not logged.

Website identity is the URL origin: URL parsing normalizes case, default ports and trailing slash; input paths/query/fragments are discarded. Different schemes/subdomains remain different origins. Unsupported schemes, credentials, nonstandard ports and explicit nonpublic IPs are rejected before job creation; DNS is checked when connecting, so a hostname resolving privately becomes an explicit crawl failure.

## Crawler policy
Only direct HTTP(S) connections are used; no environment proxy or access-control bypass. Validate every DNS answer, pin a public answer into the connection lookup, retain original TLS hostname/certificate verification, and check the resulting socket address before handing it to HTTP. Recheck redirects. Five redirects maximum; DNS/connect 5s, headers/body 10s, request 15s; 2 MiB encoded/decompressed body limits. At most three attempts for transient failures (408/429/500/502/503/504 and transport failures), with exponential delay/jitter. Permanent denials are not retried. Requests are sequential within a job. Robots declarations and crawl delays are honored; unsupported delays above 30 seconds fail explicitly. Missing robots is allowed only for 404; unavailable/denied robots fails closed.

Sitemap roots come from robots and standard fallback filenames; traverse at most 40 maps, with bounded body size and no XML entities/DOCTYPE. Blog/post map hints and generic blog/article/post URL paths identify candidates. Explicit CollectionPage metadata distinguishes blog indexes from articles; no site-specific discovery logic. Failed selected URLs retain their slots; no silent replacement. HTML collected during eligibility inspection is reused for analysis. Original selected order/provenance is persisted before page commits. This is intentionally heuristic and does not promise support for every CMS or JavaScript-only site.

Extraction v1 strips boilerplate, counts English words/bigrams, boosts title/heading evidence, and applies stable score/tie ordering. Up to five repeated supported terms; sparse content is an explicit failure. Implemented SEO checks concern title presence/length, description, H1 count and missing image alt attributes; advisory findings are labeled. No external AI/SEO service or fabricated findings.

## Durable processing
A client and its job are inserted in one transaction; PostgreSQL enforces owner/origin uniqueness. Workers claim with SKIP LOCKED, database-time 60-second leases and random fencing tokens, renewed every 15 seconds. Page data, keyword updates, findings and checkpoint success share a transaction under the current unexpired token's row lock. Network runs outside transactions. Lost leases prevent any further commits.

Expired work can be claimed at most three times before RECOVERY_EXHAUSTED. Successful checkpoints remain; eligible manual retry queues only unfinished/transiently failed selections and resets the recovery budget. Concurrent retry attempts serialize on the job row. Permanent failures cannot be retried through the UI. Graceful shutdown stops taking jobs and requeues pending work after a safe boundary within its attempt budget; forced termination relies on lease expiry. Compose allows 60 seconds for shutdown. Discovery/fetch limits bound work; crashed processes never receive implicit write permission.

Use `docker compose logs worker` for sanitized job/client correlation, or the owned crawl status API/UI for selected URLs and failures. `/api/live` is process liveness; `/api/health` checks database readiness. There is no external alerting/backup system. Restore database connectivity/configuration before retrying; do not treat liveness as readiness.

## Seed and time
Local demo identities are reserved; an existing account with a different password is not overwritten. Successful ingestion is reused on reruns, preserving selected pages and terms. Fixing a permanent source failure requires an explicit operator decision; seed does not waive missing live data. Seed targets the two demo users and their subsequent clients, preserving unrelated accounts/data. Only those users' extracted pairs receive simulated ranks.

Rank seed v1 anchors at 2026-11-15 12:00:00 UTC. SHA-256 of stable website/page/term/date input produces positions 1–100. Generate at least 365 days, extending to ceil(50000/pairCount) days as needed, bounded at 3660; fewer than fourteen pairs fails rather than fabricating terms. Composite keyword/time primary key and positive-position check enforce integrity; inserts skip existing timestamps. The fixed anchor makes results reproducible; future periods legitimately show no snapshots.

Toronto inclusive dates use Temporal/IANA midnight boundaries and a half-open UTC interval. Dates must be real ISO calendar dates, ordered and within a ten-year bound. Identical terms on different pages never share keyword IDs. Missing ranks stay null/absent. Lists paginate twenty pages before loading keyword details and use index-backed lateral latest-snapshot lookups.

## Delivery and local development
Use `npm run worker` for a host worker after building; Compose starts its own worker automatically. For host source development, stop only this project's web/API services before using their ports. Isolated browser tests never reuse existing servers. CI runs deterministic fixtures, PostgreSQL and desktop/mobile Chromium; live-site availability is a separate required acceptance command. Benchmark creates five temporary owners with copies of real extracted page/keyword/history data, measures actual HTTP with five authenticated concurrent users and removes its fixtures afterward. Results include EXPLAIN ANALYZE and machine/version details.

For a separate clean-checkout proof while the normal app runs, set `WEB_PORT=15174` and `POSTGRES_PORT=55440` in that checkout's ignored .env and use `docker compose -p fieldwork-review ...`. Keep each checkout's credential with its own volume. Do not reset existing volumes to fix credential mismatches. The root README is the reviewer entrypoint; implementation-plan.md and verification.md replace GSD tracking.
